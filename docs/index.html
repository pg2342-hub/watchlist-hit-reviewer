Watchlist Hit Reviewer

An agent for KYC teams on Footprint. When an onboarding lands in manual review with an OFAC hit, it reads the risk signals, decrypts only the fields the review needs, has Claude compare each hit with the customer under a written procedure, and posts a pass only when code confirms the hit is not the customer. Everything else goes to an analyst with a case brief.

How it works

Footprint flags the name hit; the agent does the analyst's first pass. Claude proposes a call for every hit and writes the reasoning. Code then checks the one fact the call rests on before anything is written back, and the agent can only ever post a pass. A fail, or anything it cannot settle, stays with a person.

1Receive

A signed webhook. footprint.onboarding.completed with requires_manual_review, checked against its Svix signature. Anything else is ignored.

2Read

Risk signals, then a scoped decrypt. It stops unless a signal is watchlist_hit_ofac, then decrypts name, DOB, nationality, address and the ID document's DOB and gender, with a reason Footprint logs. No SSN.

3Review

Every hit against the SDN record. Candidate entries come from the OFAC SDN list. Claude compares DOB, gender, nationality and aliases under the written procedure and proposes clear or escalate.

4Guard and write

Code confirms, then writes. A clear stands only if code confirms the deciding fact; a listed DOB equal to the customer's always escalates. A pass is posted only when every hit is cleared.

Backtest before it touches a queue

The same agent ran on 40 past reviews, 3 times each, and every call was compared with the analyst's. It agreed with the analyst on hits it cleared, with 0 wrong clears across 59 hits on run 1, and posted a pass for 21 of 40 customers. A name-score cutoff, the obvious shortcut, cleared 2 listed people who onboarded under another spelling.

Limits

  • Footprint's sandbox needs company approval, so Footprint is not called here. The client sends the requests Footprint's public API reference describes, and a local stand-in answers them in the same shapes. The document field names (document.passport.dob and similar) should be confirmed on an account.
  • Customers and the analysts' past calls are constructed; the list entries are real. A bank's own past reviews would replace the 40 cases before any pilot.
  • Candidate list entries come from this repo's own screen of the SDN list, at the same threshold that raised the hit. Footprint's own match details, where an account exposes them, would replace that step.

Data

List entries are real: the public OFAC SDN list from the U.S. Treasury Sanctions List Service, fetched 2026-11-24 by this repo's own workflow. Customers, their records, the analysts' past calls and the review procedure are constructed. Footprint requests follow its public API reference and are answered by a local stand-in.

Run it yourself

Python 3.10+.

pip install -e ".[dev]"
pytest -q
python scripts/build_demo.py

Against Footprint: set FOOTPRINT_API_KEY, FOOTPRINT_WEBHOOK_SECRET and ANTHROPIC_API_KEY, then python -m watchlist.server.
