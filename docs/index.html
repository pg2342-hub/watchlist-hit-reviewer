Why a backtest comes first

Most sanctions name hits are not the listed person, so a reviewer that agrees with analysts most of the time looks ready long before it is. The question a bank asks is narrower: on our own past cases, did it ever clear someone our analyst escalated? Here the Claude reviewer agreed with the analyst on 59 of 59 hits on run 1, with 0 wrong clears, and 41 hits could post a clear without an analyst. The name-score cutoff cleared 2 listed people who onboarded under another spelling.

Recorded live run: claude-opus-5-5, one call per customer, mean $0.0267 and 7.0 s per customer; judge $1.60 in total for all 3 runs. CI replays the recorded replies through the current code, so it needs no API key.

Where every hit landed

All 59 hits on run 1, grouped by the analyst's call. A hatched block is a clear the reviewer proposed and code blocked because it could not confirm the deciding fact.

Guardrail blocks on run 1: 0. Code posts a clear only when the customer's DOB differs from every listed DOB, or both genders are on file and differ with no listed DOB matching; a listed full DOB equal to the customer's always escalates.

Data

List entries are real: the public OFAC SDN list from the U.S. Treasury Sanctions List Service, fetched 2026-11-24 by this repo's own workflow. Customers, their records and the analysts' past calls are constructed, and so is the review procedure. Footprint request shapes follow its public API reference; Footprint is not called.
